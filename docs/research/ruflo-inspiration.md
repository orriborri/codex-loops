# Ruflo investigation for Codex loops

Inspected the project at commit `5f3dacc54b7279e39b172d6027d7989791448e2e` (2026-11-01). Links below are pinned to that snapshot. Findings describe inspected components, not an audit of the whole project. No Ruflo package was installed or executed.

## 1. Test-driven repair receipts

The [test-driven-repair implementation](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-testgen/scripts/tdd-repair/tdd-repair.mjs) runs a configured test before the model, snapshots the named test file, runs a bounded repair, detects if that file was modified, then reruns the test and reports before/after status and per-attempt data. Its accompanying [skill](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-testgen/skills/tdd-repair/SKILL.md) notes that Bash is not a sandbox; a source comment claiming the reverse must not be treated as evidence of isolation. The code checks the specified test file only; passing one selected test does not prove the whole suite or GitHub CI passes. Its cost aggregation falls back to zero for missing usage, which should not be copied as a measured cost.

**Adaptation:** When an administrator has enabled a trusted reproducible test command, record whether the same regression IDs observed before a repair still fail afterward, in fresh credential-free test containers. Use a bounded receipt with `passed`, `failed`, or `unknown`, and report unknown on timeout, bad or inconsistent JUnit, removed/skipped tests, or test tampering. Treat the receipt as advisory or a reason to stop, never as an alternative to authoritative GitHub CI and an independent review. Codex loops already supports a configured pre-repair head/base JUnit comparison; building on that is smaller and more directly useful than adopting Ruflo's Claude-specific repair runner.

## 2. Safe bounded recall, not a self-modifying policy

The [AgentDB recall implementation](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-agentdb/hooks/recall.ts) caps retrieval at five items, 400 characters per item, and 1500 characters total, with a score threshold and prompt eligibility checks. Its [ADR 445](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/docs/adr/ADR-445-agentdb-as-a-mod.md) specifies off-by-default recall with a deadline, per-item source/age, untrusted framing and explicit limits; it excludes automatic feedback writes pending stronger evidence. Its [guard](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-agentdb/hooks/guard.ts) rejects suspected secrets or oversized memory writes. The [screen](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-agentdb/hooks/screen.ts) uses pattern matching; ADR 445 acknowledges detection is heuristic and cannot prove safety.

**Adaptation:** If past lessons are later used, start with opt-in, small, source-linked, repository-scoped summaries whose provenance and timestamps are visible, treated solely as untrusted evidence. Suppress unsafe/oversized content and impose strict count and length limits; maintain a no-recall fallback. Do not automatically promote model text to trusted instructions or policy, infer secret safety from pattern checks, or introduce a vector database without evidence of need. A safer first slice is to surface metadata/counts from existing workflow records without adding free-text recall at all.

## 3. Observe routing outcomes before automating routing

Ruflo's actual [model router](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/%40claude-flow/cli/src/ruvector/model-router.ts) describes a lexical complexity heuristic with a persisted bandit; an optional neural route requires explicit gating, embeddings and usable artifacts. The project itself documents an earlier mismatch between neural-routing claims and wiring in [ADR 148](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/v3/docs/adr/ADR-148-fastgrnn-router-artifact-lifecycle.md). The [cost tracker outcome script](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-cost-tracker/scripts/outcome.mjs) accepts an explicit `success`, `escalated`, or `failure` label and sends it to the router. This does not independently establish task quality.

**Adaptation:** Report actual model job outcomes and separately observed review/CI/merge results, with the model identity and task/revision provenance when available. Never label a successful model invocation as a correct fix, confidence as measured accuracy, wall time as token count, or absent usage as zero cost. Use the resulting aggregate to evaluate model choices offline before adding adaptive routing. Existing Opik and model job metrics already implement much of this, so extend only where a demonstrated gap exists.

## 4. Bounded work and unsupported claims

The [test repair code](https://github.com/ruvnet/ruflo/blob/5f3dacc54b7279e39b172d6027d7989791448e2e/plugins/ruflo-testgen/scripts/tdd-repair/tdd-repair.mjs) accepts an explicit attempt cap, per-attempt USD parameter, and timeout, but those caps are tied to the invoked CLI; they cannot be assumed to apply to Codex or subscription credentials. Codex loops already bounds retries and wall time. Any future budget feature must distinguish true reported tokens/costs from attempts/time and state the enforcement boundary.

The repository README labels parts of the memory/learning flow conceptual. The presence of a router, bandit, vector store, 100+ agents or an accuracy claim does not demonstrate benefit for this project's tasks. Do not introduce federation, autonomous policy changes, broad swarms, or a vector dependency merely because the upstream project offers them.
